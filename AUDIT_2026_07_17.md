## 5. Root-cause deep dives (5 Whys) — every P1

### 5.1 🔴 Geo-lock bypass **[FIXED]**
1. **Symptom:** A share-token holder unlocks a location-gated memory's photos/text/audio from anywhere, without physically visiting.
2. **Trigger:** Open the public teaser `GET /api/memory-shares/{token}`, read the returned coordinates, replay them as GPS to `POST .../reveal`.
3. **Code flaw:** `getShareTeaser` set `approximateLatitude/Longitude` to `memory.getLatitude()/getLongitude()` — the **exact** stored coords, no jitter despite the field name. `revealShare` unlocks when client-submitted coords are within 100m of those same exact coords. The teaser hands the attacker the exact value the gate checks.
4. **Architectural gap:** The teaser (a "point the recipient toward the place" affordance) and the reveal gate (a physical-presence proof) were coupled to the *same* precise coordinate, so the display value doubles as the unlock secret. Same class as the 2026-05-25 fix — a new vector on the same seam.
5. **Root correction:** Introduced `coarsen()` — teaser coords are snapped to a configurable grid (`app.memory.teaser-precision-degrees`, default `0.01°` ≈ 1.1km, guaranteed coarser than the 100m unlock radius). The neighborhood pointer still works (`placeLabel` carries the real name); a replayed teaser coordinate can no longer land within 100m of the true point. Pair with rate-limiting (SEC-P2) to close residual brute-force. **Files:** `MemoryService.java:49-56, 371-372, +coarsen()`. **Verified:** `:memory:compileJava` + tests green.

### 5.2 🔴 MemoryService stacked N+1s **[RECOMMENDED]**
1. **Symptom:** The 3 core /memories tabs slow down linearly with rows per tab.
2. **Trigger:** A user with N memories loads a tab → ~2N+N extra queries.
3. **Code flaw:** `toResponse()` calls the single-arg `creatorSummary()` (findById + findByUserId = 2 queries) **and** `countByParentMemoryIdAndDeletedAtIsNull()` per row. The surrounding `recipientsByMemory` batching is undone by this per-row path.
4. **Architectural gap:** `toResponse` was written for the single-item case and reused in list loops; the batched maps exist but aren't threaded into it.
5. **Root correction (documented, not shipped):** Pass the already-batched users/profiles maps into `toResponse`, call the two-arg `creatorSummary(id, users, profiles)`; batch reply counts with one `GROUP BY parent_memory_id` over the page's ids. Not shipped blind because it changes a hot read path's data assembly — verify row-for-row against current output with a running DB first.

### 5.3 🔴 Unbounded/ephemeral container logs **[FIXED]**
1. **Symptom:** After a prod failure, logs are gone the next day; disk can also fill.
2. **Trigger:** Any redeploy (recreates containers, discarding `docker logs`); or enough time for stdout to grow unbounded.
3. **Code flaw:** No `logging:` block on any service in `docker-compose.prod.yml`; backend logs stdout-only (no file appender).
4. **Architectural gap:** Logging retention was never declared — the default json-file driver has no size cap and container-local logs are the only copy.
5. **Root correction:** Added a shared `x-logging` anchor (json-file, `max-size:50m`, `max-file:3`) on all four services — bounds disk and keeps rotated local history. Documented the follow-on (ship to an aggregator/persistent volume for cross-redeploy history). **Verified:** compose YAML parses.

### 5.4 🔴 AI provider failures swallowed **[FIXED]**
1. **Symptom:** An Anthropic/OpenAI/Gemini outage or bad key surfaces to the user as an empty/generic-500 response with nothing in the logs.
2. **Trigger:** Any non-2xx from the provider, or a stream parse error.
3. **Code flaw:** All 3 clients never checked `response.statusCode()` and used `catch (Exception ignored){}`; the `ai` module had no SLF4J logger at all.
4. **Architectural gap:** The clients were written for the happy path; failure was never an observable event.
5. **Root correction:** Added loggers to all 3 clients; on `statusCode >= 400` they log provider + status + a 500-char body snippet and `completeWithError` with a typed message; parse/stream/request errors now log at debug/warn instead of vanishing. **Verified:** `:ai:compileJava` + tests green.

## 9. 2026-08-06 BOR-81 follow-up fixes

### 9.1 Frontend non-render crash capture [FIXED]
1. Symptom: event-handler errors and unhandled promise rejections can fail silently outside React render boundaries.
2. Trigger: async browser APIs, rejected fetch chains, or event callbacks throw after the component tree has mounted.
3. Code flaw: `RootErrorBoundary` catches render lifecycle failures only; no global `error` / `unhandledrejection` listeners existed.
4. Architectural gap: frontend observability depended on React boundaries even though not all browser failures pass through React.
5. Root correction: added `GlobalErrorCapture`, mounted it in the root layout, capped in-memory crash history at 20 entries, and logged normalized error details for DevTools / WebView log collection.

### 9.2 Auth token endpoint failures misclassified [FIXED]
1. Symptom: a real `/api/auth/token` failure looked identical to a logged-out user.
2. Trigger: token endpoint returns 5xx/network failure while a protected page loads.
3. Code flaw: `useAccessToken` ignored `res.ok`, parsed every response as JSON, and collapsed all failures to `null`.
4. Architectural gap: auth state and infrastructure failures used the same nullable return path.
5. Root correction: `401` now means unauthenticated, non-401 failures produce an explicit error and console evidence, and the shared cache is cleared on failure.

### 9.3 Remaining swallowed serialization failures [FIXED]
1. Symptom: malformed OpenAI tool-call arguments or notification payload serialization failures left no diagnostic trail.
2. Trigger: provider streams invalid tool JSON, or notification `data` cannot be serialized.
3. Code flaw: catch blocks intentionally swallowed exceptions.
4. Architectural gap: non-fatal fallbacks were implemented without preserving root-cause evidence.
5. Root correction: added debug/warn logging while preserving existing non-fatal fallback behavior.

**Verification:** `npm.cmd run lint` passes with existing warnings; `npx.cmd tsc --noEmit --incremental false` passes; `:ai:test`, `:notification:compileJava`, and `:memory:test` pass with workspace-local Gradle cache.
